## Acquisition and frozen evidence

The only data acquisition used the official ECB Data Portal API:

```bash
curl --fail --silent --show-error --location \
  --dump-header /tmp/qhapaq-ecb-headers.txt \
  --output /tmp/qhapaq-ecb-exr.csv \
  'https://data-api.ecb.europa.eu/service/data/EXR/D.USD+GBP+JPY+CHF.EUR.SP00.A?startPeriod=2015-01-01&endPeriod=2026-08-31&format=csvdata'
```

## Learning, limitations, and next action

The CSV's ECB `KEY` values include the `EXR.` dataflow prefix, while the canonical series IDs are
the dimension keys such as `D.USD.EUR.SP00.A`; the loader validates both representations rather
than conflating them. The requested start was a holiday, so the first actual observation is
2015-01-02. Each series has the same 2985-date calendar, and the latest observation is exactly the
requested 2026-08-31 boundary.

This increment verifies dataset bytes, provenance metadata, dimensions, values, counts, ordering,
and point-in-time filtering. ECB history may later be revised, but this repository snapshot remains
byte-frozen. It does not provide a research-result manifest, chart, or investment claim. The next
bounded increment is a verified Research Tear Sheet that consumes only this committed loader and
preserves the dataset and manifest identities in its result evidence.
